# AGENTS.md

NexaCart is a Java 21 / Spring Boot 4 e-commerce REST API implemented as a modular monolith. Business code is organized by domain package; PostgreSQL is the only supported database and Flyway owns the schema.

## Start here

Read in this order before changing code:

1. [README.md](README.md) — purpose, quick start, verification.
2. [docs/README.md](docs/README.md) — documentation index and source-of-truth map.
3. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — boundaries, persistence, transactions, security, and trade-offs.
4. [docs/PROJECT_STRUCTURE.md](docs/PROJECT_STRUCTURE.md) — package responsibilities and where new code belongs.
5. [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) — conventions, migrations, testing, and pitfalls.

Use [docs/API.md](docs/API.md) for the HTTP contract and [docs/OPERATIONS.md](docs/OPERATIONS.md) for configuration, profiles, and limitations.

## Commands

```bash
mvn test                       # unit + integration tests (Docker required)
mvn clean verify               # tests, schema validation, packaged JAR
mvn -DskipTests package        # package only
SPRING_PROFILES_ACTIVE=dev mvn spring-boot:run   # requires PostgreSQL + NEXACART_JWT_SECRET
docker compose up -d postgres  # local database
docker compose up --build      # full local stack
```

Integration tests use PostgreSQL 17 via Testcontainers. There is intentionally no H2 fallback or embedded database.

## Where work belongs

- New business capability: new package under `src/main/java/com/nexacart/<domain>/` with `controller`, `dto`, `entity`, `repository`, and `service` as needed.
- New endpoint: existing domain's `controller`/`service`/`dto`.
- Shared domain-neutral helper: `common/`; do not put domain rules there.
- Unit test: package of the class under test.
- Integration test: domain test package, extending `com.nexacart.support.IntegrationTestBase`.
- Schema change: new `V<n>__description.sql` under `src/main/resources/db/migration/`. Never edit an applied migration.
- Runtime setting: `NexaCartProperties`, `application.yml`, the relevant profile, `.env.example`, `compose.yaml` when Compose should forward it, and `docs/OPERATIONS.md`.
- API behavior: update `docs/API.md` and `docs/nexacart.postman_collection.json`.
- Docs: update `docs/README.md` when adding or renaming a document.

## Non-negotiable conventions

- Keep the dependency direction `controller -> service -> repository`. Controllers handle HTTP only; services own business rules and `@Transactional` boundaries; repositories handle persistence.
- Never serialize JPA entities or accept them as request bodies. Use DTO records and explicit mapping.
- Entity ownership checks belong in services. Cross-customer access returns 404, not 403.
- Order checkout requires `Idempotency-Key` and relies on the unique `(user_id, idempotency_key)` constraint; preserve the cart-lock and inventory-lock ordering.
- Inventory changes must lock rows in ascending product-ID order, validate before mutating, update the balance, and write an `InventoryTransaction` ledger row.
- Money uses `BigDecimal` scale 2; timestamps use `Instant` in UTC. Never trust client-provided prices, totals, roles, or review eligibility.
- Never enable the payment simulator or dev seeding in `prod`/`production`.
- Never log passwords, bearer tokens, or secrets. Keep `NEXACART_JWT_SECRET` out of source control.
- Preserve `ddl-auto: validate` and Flyway `clean-disabled`.

## Generated and immutable files

- `target/` and packaged JARs are generated by Maven; do not edit or commit them.
- Applied Flyway migrations are immutable. Add a new migration for every schema change.
- `docs/nexacart.postman_collection.json` is maintained manually.
- Do not commit `.env`, logs, IDE state, or build output.

## Before finishing

1. `mvn clean verify` must pass; Docker must be running for integration tests.
2. Review `git diff` and `git diff --check`; remove unrelated changes.
3. Update the relevant docs and links when behavior, configuration, layout, or the API changes.
4. Do not weaken tests, lower validation, or disable checks to obtain a passing build.
